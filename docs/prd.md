# AI 面试模拟器 — 前端产品需求文档

---

## 1. 产品定义

**产品名称**：AI 面试模拟器

**一句话描述**：面向求职者的 AI 驱动面试练习工具——用户提供岗位 JD 和简历，AI 自动生成面试题并进行多轮追问，面试结束后给出评分和改进建议。

**核心价值**：在零压力的环境中反复练习面试，通过量化和反馈持续提升面试能力。

---

## 2. 目标用户

| 画像 | 特征 | 核心痛点 |
|---|---|---|
| 在校生 | 大三/大四，即将找实习 | 从未经历过正式面试，不知道会被问什么 |
| 应届生 | 正在海投，面试密集 | 需要在不同公司/岗位间快速切换练习 |
| 转行者 | 有工作经验但换方向 | 新领域的面试题型不熟悉 |

---

## 3. 核心使用场景

| 场景 | 用户故事 |
|---|---|
| **考前突击** | 明天面字节，今晚照着 JD 练 5 道技术题，AI 追问深挖我的弱项 |
| **复盘提升** | 上次面挂了，回来看 AI 当时的反馈，发现"表达不够结构化"是硬伤 |
| **日常刷题** | 每天练 3 道，保持面试手感 |
| **跨岗适应** | 同一个公司面了技术和 HR 两轮，分别用不同类型的模拟准备 |

---

## 4. 页面结构

```
/login                  登录页
/home                   首页（工作台）
/interview/create       创建面试
/interview/history      面试记录
/interview/:id          面试对话（核心页面）
/interview/stats        面试统计（预留，暂不实现）
```

---

## 5. 各页面功能模块

### 5.1 登录页 `/login`

**功能**：
- 品牌展示（Logo + 产品名 + 一句话介绍）
- 用户名/密码输入
- 记住密码
- 登录按钮
- 注册引导链接（暂不可用，提示"即将开放"）

**交互**：
- 回车触发登录
- 登录失败时提示错误信息
- 登录成功后跳转首页

### 5.2 首页 `/home`

**功能模块**：

| 模块 | 内容 |
|---|---|
| 问候区 | 分时段问候（上午好/下午好/晚上好），配一句鼓励文案 |
| 统计卡片 | 总面试次数、平均得分、今日练习次数（数字大，单位小） |
| 快捷入口 | 2 个大卡片：「开始新面试」「查看面试记录」，点击跳转 |
| 最近记录 | 最近 5 条面试，显示公司、岗位、得分、日期，点击跳转详情 |

**交互**：
- 统计卡片可点击，点击"总面试次数"跳转记录页
- 最近记录整行可点

### 5.3 创建面试 `/interview/create`

**表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 目标公司 | 文本输入 | 是 | 自由输入 |
| 目标岗位 | 文本输入 | 是 | 自由输入 |
| 岗位 JD | 多行文本 | 否 | 粘贴 JD，AI 据此出题 |
| 简历 | 文件上传 | 否 | PDF/Word/TXT/Markdown，用于 AI 针对性提问 |
| 面试类型 | 单选 | 是 | 技术面 / HR 面 / 综合面 |
| 题目数量 | 选择 | 是 | 预设 3/5/8/10/15 + 自定义输入（1-30） |

**交互**：
- 公司和岗位为空时，点击开始弹 Toast 提示
- 点击开始后跳转对话页，URL 带参数传递所有表单数据
- 上传区支持拖拽和点击
- 重置按钮清空所有字段

### 5.4 面试记录 `/interview/history`

**功能**：
- 搜索框：按公司名或岗位名模糊搜索
- 类型筛选：全部 / 技术面 / HR 面 / 综合面
- 数据列表：ID、公司、岗位、类型、日期、得分、时长
- 分页器
- 创建面试按钮（快捷入口）

**交互**：
- 搜索和筛选实时生效
- 列表行点击跳转对应面试详情
- 得分用颜色区分：绿（≥80）、黄（60-79）、红（<60）

**空状态**："还没有面试记录，去创建你的第一场模拟面试吧"，下方放创建按钮。

### 5.5 面试对话 `/interview/:id`（核心页面）

**页面加载流程**：

```
进入页面 → 读取 URL 参数 → 调 AI 生成题目 → 显示首题 → 用户作答 → AI 追问 → 循环 → 结束 → 评估报告
```

**功能模块**：

| 模块 | 内容 |
|---|---|
| 信息栏 | 公司-岗位、面试类型标签、当前题号/总题数、结束面试按钮 |
| 消息列表 | AI 消息（左）、用户消息（右），每条带时间戳 |
| AI 思考中 | 三点闪烁动画 + 文字提示 |
| 输入区 | 多行文本框 + 发送按钮 + 快捷键提示（Ctrl+Enter） |
| 结果弹窗 | 综合得分 + 各维度星级评价 + AI 改进建议文字 |

**各状态处理**：

| 状态 | 表现 |
|---|---|
| 题目生成中 | 首条消息显示"AI 面试官正在准备面试题，请稍候..." |
| AI 追问中 | 消息列表底部三点动画 + 输入框禁用 + 发送按钮 loading |
| 面试正常进行 | 消息逐条追加，自动滚动到底部 |
| 面试结束 | 弹出结果面板，展示评分和反馈 |
| 题目生成失败 | Toast 报错，提供返回按钮 |
| AI 追问失败 | Toast 报错，输入框恢复可用，用户可重试 |
| 用户快速连发 | AI 回复前输入框禁用，防止消息顺序混乱 |
| 页面刷新/误关闭 | 面试进行中离开时弹确认框 |

## 6. 视觉方向参考（非设计稿）

用户提供的三个参考：

| 参考 | 提取的设计原则 |
|---|---|
| **Hayden Bleasel 个人网站** | 极简配色（几乎只有黑白）、页面重心在交互而非装饰、时间线式的叙事结构 |
| **Streamline Freehand 图标** | 手绘线条、不完美的笔触、有人味而非机械感 |
| **EverSwap (Lusion)** | 仅用双色、滚动驱动叙事、大面积留白 |

**用户倾向的方向**：
- 配色克制，不要多彩
- 图标用手绘风格替代几何图标
- 整体气质：像在纸上答题，专业但不严肃
- 排版有节奏感，标题和正文有明确区分

## 7. 全局交互规范

| 规范 | 说明 |
|---|---|
| 表单校验 | 实时校验 + 提交时校验，错误信息在字段下方 |
| 按钮状态 | 主操作按钮有 normal/hover/active/loading/disabled 五态 |
| Toast 提示 | 成功用绿色、警告用黄色、错误用红色 |
| 页面标题 | 浏览器标签页显示当前页面名称 |
| 路由守卫 | 未登录时所有页面重定向到登录页 |
| 数据持久化 | 登录状态存 localStorage |

## 8. 移动端适配

| 优先级 | 说明 |
|---|---|
| **优先桌面端** | ≥768px，当前阶段以桌面端体验为主 |
| **后续移动端** | <768px，核心交互需可用（对话、创建、查看记录） |

移动端关键适配点：
- 顶栏导航 → 汉堡菜单
- 统计卡片 → 垂直堆叠
- 表格 → 卡片化布局
- 对话页 → 全屏，键盘弹起时消息区自适应
